# RunVision — контекст проекта

Мобильное (в первую очередь) веб-приложение, в котором пользователь гибко настраивает
внешний вид карточки тренировки, чтобы поделиться ею. Источник данных — GPX-файл.
Сценарии «Фото» (PNG-карточка) и «Видео» (MP4: точка бежит по треку; все три стиля).

Общение с пользователем, комментарии в коде и сообщения коммитов — на русском.

## Стек и команды

Vue 3.5 (`<script setup>`, TypeScript), Vuetify 4, Pinia, vue-router (hash), Vite, Vitest,
html-to-image (экспорт PNG). Деплой — GitHub Pages (`base: /run-vision/`, workflow на `main`).

```sh
npm run dev          # фронт + сервер API (dev:front — только фронт)
npx vue-tsc --build  # типы
npx eslint .         # линтер (oxlint ругается только на старый код карты — это известно)
npx prettier --write src
npx vitest run       # юнит-тесты (раскладка показателей)
npx vite build
```

## Пользовательский сценарий (роуты)

1. `/` — `ImportView`: кнопка «Загрузить GPX» по центру (+ ссылка «Показать все файлы»
   для iPhone, где фильтр по типу не пускает .gpx). После загрузки → `/share`.
2. `/share` — `ShareView`: карточка тренировки, выбор «Фото / Видео», для фото — карусель
   из трёх шаблонов (Минимализм, Топография, Телеметрия; «Свой вариант» убран). Превью
   в карусели — в цветах пресета шаблона (у настроенного — в цветах черновика).
   «Продолжить» → редактор. Для видео — та же карусель (`videoTemplateId` в `share.store`,
   доступные — `VIDEO_TEMPLATE_IDS`, остальные приглушены с пометкой «Скоро»). На каждом
   превью слева сверху значок типа — фото или видео (как на плитках «Моих шаблонов»;
   `shareType` у `PhotoTemplateCarousel` → `PhotoTemplateCard`).
3. `/share/photo/editor` — `PhotoEditorView`: полноэкранный редактор (шапка приложения
   скрыта через `meta.hideAppHeader`). `/share/video/editor` — тот же компонент с
   `mode: 'video'` (см. «Видео»).

4. `/account` — `AccountView` («Мои шаблоны», `meta.requiresAuth`), `/account/templates/:id` —
   `SavedTemplateView`. Гостя — на вход с `?redirect=`; без связи с сервером — пускаем.
5. `/login`, `/register` — `AuthView` (один компонент на оба режима, `meta.guestOnly`:
   вошедшего уводит на `/`). После входа — назад по `?redirect=` (только внутренние пути,
   `router/redirect.ts`). В `AppHeader` справа «Войти» или `UserMenu` (email, тариф, «Выйти»,
   «Персональные данные», «Удалить аккаунт» — `DeleteAccountDialog`, с паролем).
6. `/forgot-password` (`ForgotPasswordView`, почта → письмо; `?email=` — подставить) и
   `/reset-password?token=` (`ResetPasswordView`, ссылка из письма → новый пароль → вход).
   `/privacy` и `/consent` — `LegalView` (политика и согласие). Стили всех экранов входа —
   общий `auth-view.css`, обход автозаполнения — `createAutofillHandler` (`autofill.ts`).

Страницы с `meta.requiresActivity` без загруженного GPX редиректят на `/`.
Старая 3D-карта (`views/activity-view`) оставлена в коде, но маршрут не зарегистрирован.

## Редактор (устройство экрана)

- Сверху `EditorTopBar` (вариант «стрелка + капсула», выбран пользователем): круглая
  кнопка ← слева, по центру капсула `EditorHistoryActions` — отменить · повторить │ сбросить
  (до 10 шагов, `useUndoRedo` с debounce 400 мс — серия изменений = один шаг; сброс —
  с диалогом), справа «Сохранить» пилюлей (рендер PNG → `ShareCardResultDialog` →
  share/скачивание). Помещается и на 320px (iPhone SE).
- «Добавить» — панель на три строки ниже остальных (`ADD_PANEL_MAX_HEIGHT`, не ниже 144px:
  на iPhone SE иначе оставалась одна кнопка без списка), кнопка
  «Добавить все показатели» (с данными); «Показатели» — кнопка
  «удалить все». Без показателей пункт «Показатели» неактивен.
- В центре карточка `ShareCardArtwork` внутри `FitToBox`: карточка всегда видна целиком
  без прокрутки и уменьшается (CSS transform) под свободное место.
- Снизу `EditorToolbar` (инструменты из `tools/editor-tools.ts`): Добавить, Фон,
  Оформление (цветовые пресеты), Трек, Показатели. Панель `EditorToolPanel` выезжает с
  анимацией (grid-template-rows), без анимации при переключении между инструментами.
  «Трек»/«Показатели» неактивны, если элемента нет на карточке.
- **Ритм панелей** (проверять на iPhone 13 и SE): от «ручки» до первого ряда и от последнего
  до низа — 14px, между рядами — 12px, края — 16px. `OptionTileRow` сам даёт 8px сверху
  (место под кнопку удаления на плитке), поэтому панель с кнопками сверху добавляет себе
  `padding-top: 8px`, а между кнопками и плитками — gap 4px + 8px ряда. Кнопки — 36px в
  высоту. Ползунки — `v-slider` (поворот трека и перемотка видео — одинаковые). Ряды
  кнопок на узком экране не обрезаются: «График»/«Виджеты» переносят «Подписи / Без»
  (`flex-wrap`), «Показатели» — сетка в две строки по `@container` (≤344px).
- Разделитель после закреплённых плиток («Цвет») в `OptionTileRow` — по высоте плитки
  (`::after`), а не рамкой блока: рамка тянулась на отступ сверху и уходила выше плиток (было).
- **«Цвет трека» — внутри плитки «Цвет»** (`ColorOptionTile`, проп `track-color` + событие
  `use-track-color`): плитка пополам: сверху палитра, снизу кнопка «Цвет трека» с рамкой (подсвечена,
  пока цвет как у трека; свой цвет — подсвечена вся плитка). Палитра (`label`) и кнопка —
  соседи, не вложены: иначе тап по кнопке открывал палитру. Так в «Графике», «Виджетах» и
  у точки видео; отдельной кнопки «Цвет трека» в рядах кнопок больше нет.
- Горизонтальные панели собраны из `OptionTile` / `OptionTileRow` / `ColorOptionTile`
  (одинаковая высота у Фона, Оформления и Трека). `OptionTileRow` при открытии меню сразу
  (без анимации) прокручивает ряд к выбранной плитке — по центру.
- Значения по умолчанию у шаблонов: пресет — `presetId` в `photo-templates.ts`
  (Минимализм — «Закат», Топография — «Неон», Телеметрия — «Солнце»), стили трека и
  показателей — `TEMPLATE_STYLES` в `useShareCardSettings` (Минимализм: «Тень» + «Скорость»;
  Топография: «Плитка», карта во весь фон «В тон», наклон 60°, график «Силуэт»; Телеметрия:
  «Свечение» + «Уголки», виджеты «Изолинии»: сплиты справа, над показателями пульс/темп).
  Шаблон передаётся в `useShareCardSettings` опцией `template`.

## Карточка

- Отступ 16px со всех сторон. Элементы: название (редактируется на месте, удаляется),
  трек, показатели. Выделение тапом (`SelectionFrame` + `ArtworkElementToolbar`),
  тап мимо снимает выделение.
- **Трек** (`ArtworkRoute`) — свободный слой от низа названия до низа карточки:
  двигается, масштабируется щипком (`usePinchDrag`), на десктопе — уголок и колесо.
  Стиль трека — набор слоёв-копий линии (`activity-share-route-styles.ts`), рисует
  `RouteStyleLayers` (тот же компонент — превью в меню).
  Поворот, наклон и флажки — общие для всех шаблонов, в меню «Трек» (с картой они же
  поворачивают и наклоняют карту): `routeBearing`, `routePitch` (0/35/60°),
  `routeFlags` — флажки одной кнопкой (км + старт/финиш, по умолчанию включены во всех
  стилях; старые `routeKmMarkers`/`routeStartFinish` переводит `normalizeShareCardSettings`). Поворот на карточке — двумя пальцами (обработчик
  в `ShareCardArtwork` на всей карточке). Без карты точки считает `orientRoute`
  (`route-projection.ts`, с тестами): поворот, наклон с перспективой и заново вписывает
  в место под трек — в JS, не CSS 3D, чтобы PNG совпал с экраном. Флажки без карты —
  между точками повёрнутого трека (`index`/`t` из `getKmMarkers`), в единицах слоя.
  Превью стилей в меню «Трек» — по 200 точкам трека: с полным треком 16 плиток
  перерисовывались на каждом шаге поворота (~120 мс на шаг, меню подлагивало).
- **Показатели** — сетка из 6 колонок (⅓=2, ½=3, 1=6). Правило: в строке все показатели
  одной ширины и выровнены по её сетке. Логика — чистые функции в
  `activity-share-stat-layout.ts` (`resolveStatLayout`, `getStatDropCells`, `applyStatDrop`)
  с тестами. Перетаскивание (`useLongPressDrag`): пальцем после долгого нажатия, мышью и
  выделенный — сразу. Пунктирная сетка мест: пустая строка — по ширине перетаскиваемого,
  занятая — по ширине стоящих; бросок на другой показатель меняет их местами и размерами.
  Ширина на панели показателя — одна кнопка по кругу ⅓→½→1. Сетка «N в ряд», плотность
  (4/12/20) и стиль (16 пресетов, CSS в `ShareCardStatItem.vue`) — в меню «Показатели».
  Новый показатель получает ширину текущей сетки, если все показатели одной ширины.
- Число стилей у трека, показателей и графика одинаковое — 16; добавляя стиль одному,
  добавлять и остальным.
- Цвета: фон — в «Фоне», трек — в «Треке», текст (показатели + название) — в «Показателях».

## Видео

- Тот же редактор (`PhotoEditorView`, `mode: 'video'`), но **свой черновик**: правки
  фото-«Минимализма» не попадают в видео и в его превью в карусели (ключ `тип:шаблон`,
  см. «Черновики»). Отличия: под карточкой `VideoPlaybackBar` (▶/⏸, перемотка, время,
  длительность 5/10/15/20 с одной кнопкой по кругу), «Сохранить» делает MP4. Режим шаблона —
  как у фото (видео-шаблон, см. «Мои шаблоны»). В покое — конец ролика: точка на финише,
  итоговые цифры.
- Время → доля трека — `getRouteProgressAt` (по дистанции, последняя 1 с — пауза на финише);
  показатели — ступеньками по 0,5 с (`getStatProgress`, округление вверх: на старте не «—»),
  считаются по тренировке «до точки» (`getActivityAtProgress`: часть трека, дистанция и время
  в движении в масштабе GPX — на финише цифры как на фото). Всё в `activity-share-video.ts`,
  с тестами. Кэш значений на ступеньку — в редакторе.
- **Точка — стили, цвет, фото** (`settings.videoDot`: `style`, `color` — null = цвет трека,
  `photo` — object URL). Меню — в «Трек»: в видео переключатель «Трек / Точка» стоит в
  одном ряду с наклоном и флажками (по умолчанию «Трек», состояние в `TrackPanel`); наклон,
  флажки и поворот видны на обеих вкладках, меняются только плитки внизу. У точки — плитка
  «Цвет» с «Цвет трека» внутри (см. «Редактор»), плитка «Фото» (крестик — убрать) и стили `VIDEO_DOT_STYLES` (Классика, Точка,
  Кольцо, Неон, Мишень; под фото неактивны, как цвет фона под фото). Всё — в
  `video-dot.ts` (с тестами): геометрия — слои `getVideoDotLayers` (круги, хвостик,
  фото) в единицах слоя, их рисуют и SVG (`VideoDotMark`, проп `dot`), и холст в кадрах
  (`drawVideoDotLayers`). Фото — «пузырёк» над треком (круг с обводкой цвета точки,
  хвостик к маленькой точке на самом треке); холст рисует его из заранее декодированного
  `<img>` (`loadImage` перед записью, cover-обрезка как у `<image slice>`). Фото точки
  хранится как фото фона: черновик, файлы в сессии (`work-session`), освобождение URL;
  в шаблон не попадает (`toTemplateSettings`). Старым черновикам точку по умолчанию
  добавляет `normalizeShareCardSettings`.
- Точка (по умолчанию «Классика» — `VIDEO_DOT`: ореол, кольцо цвета текста, сердцевина
  цвета точки) — по `getTrackLocation` между уже спроецированными точками: без карты в
  `ArtworkRoute` (точки повёрнутого трека, индексы как у `projectRoute`), с картой — в
  `ArtworkMap` (точки `map.project`, индексы как у `getRouteLngLats`). Поворот/наклон/перенос
  трека и карты — как в фото.
- Маркер на графиках (`ChartMarker`: точка на линии + концы черты; SVG — `VideoChartMark`,
  размеры `VIDEO_CHART_MARKER`) — график высоты (`ArtworkElevation`) и графики-виджеты
  «Телеметрии» (`ArtworkWidget`: темп, пульс, высота). Считает `getProfileChartMarker` (тот же
  ряд под стиль и запас сверху `getElevationChartTop`, что у `ProfileChart`; `getElevationMarker`
  с тестом). В вертикальной «ленте» маркер переводится той же матрицей, что `tapeTransform`
  (`mapChartMarker`) — черта становится горизонтальной. SVG графиков `overflow: visible`.
- «Телеметрия»: сплиты и зоны — по ступеньке показателей (`statProgress` у карточки и виджета):
  сплиты впереди точки приглушены (масштаб по всей тренировке), зоны — время «до точки»
  (`getHeartRateZones(track, progress)`: границы по всей тренировке, до первых секунд — нули,
  с тестами). В ключ ступеньки экспорта входит доля, если есть сплиты/зоны (иначе кадр не
  перерендерится при тех же цифрах). Виджеты — ссылки-функции по ключу полосы (`widgetRefs`):
  они рендерятся слотом сетки, строковая ссылка хранила бы последний.
- **Флажки «выпрыгивают»** (все стили, если включены в «Треке»): флажок километра и финиш
  появляются, когда до них доходит точка, — рост от основания древка с перелётом
  (`getFlagPopScale`, `FLAG_POP_SECONDS` 0,45 с; финиш — в начале паузы на финише,
  `getTimeSinceReach`). Кольцо старта видно всегда, в покое и на фото — все флажки.
  Геометрия флажков — общая у SVG (`RouteMarkers`, проп `flagScale`) и холста
  (`route-flags.ts`: `getKmFlagShape`/`getFinishFlagShape`, `drawKmFlag`/`drawFinishFlag`,
  с тестами). Масштаб считает карточка (`flagPop` по `videoTime`/`videoDuration`), трек и
  карта переводят флажок в долю дистанции (`getFlagReach`). На время записи флажков в
  карточке нет (`flagPop` → 0) — их на каждом кадре рисует холст по `VideoMarks.flags`.
- Экспорт — `useShareVideoExport`: карточка рендерится html-to-image только при смене цифр
  (`showStatsAt` ставит ступеньку, одинаковые значения не рендерятся), точку и маркер графика
  на каждом кадре рисует холст (`drawVideoDot`, `drawChartMarker`; позиции — `getVideoMarks`
  у `ShareCardArtwork` в пикселях раскладки, тип `VideoMarks`: точка + маркеры всех графиков
  со своим цветом). Пока пишется видео, карточка не
  передаёт `progress` (`liveProgress`) ни треку, ни карте, ни графику: `export-hidden` внутри
  SVG html-to-image не учитывает — в кадрах было две точки (было).
- Кодирование (`shared/lib/video/video-writer.ts`): WebCodecs `VideoEncoder` + `mp4-muxer`,
  1080 px по ширине, 30 к/с, H.264 (в Chromium песочницы без H.264 — VP9 в MP4); без
  WebCodecs — `MediaRecorder` по `captureStream()` в реальном времени, 720 px.
  Результат — `ShareCardResultDialog` с `<video>`, сохранение — `shareOrDownloadFile`.
- Подложки карты в видео проверяет пользователь на телефоне (из песочницы тайлы недоступны).

## Шаблон «Топография» (карта)

- В `settings.map` (`ShareMapSettings`, null у других шаблонов): вид карточки `layout`
  (`block` — карта блоком, `full` — во весь фон с затемнением снизу), стиль `style`.
  Наклон и поворот карты — общие с треком (`routePitch`, `routeBearing`, меню «Трек»;
  два пальца — по всей карточке, т.к. над картой слои с `pointer-events:none`).
  При любом наклоне/повороте трек заново вписывается по центру (`fitRoute`, подгонка по
  проекции ~400 точек трека, не чаще кадра).
- Стили карты (`SHARE_MAP_STYLES` в `activity-share-map.ts`) — только Esri
  (server.arcgisonline.com: у пользователя работает, отдаёт CORS): Light/Dark Gray Canvas
  и World_Imagery + обработка растра (`raster-saturation/contrast/brightness/opacity`
  поверх цвета фона): «В тон», «Ночь», «Чертёж» (инверсия), «Винтаж», варианты спутника.
  OpenTopoMap (пёстрая), CARTO и DEM-рельеф (у пользователя не работали) — убраны.
  Превью в меню — настоящий тайл места тренировки + CSS-фильтр, приближающий обработку.
- Меню «Карта» — только вид карточки (`SegmentedGroup`) и ряд стилей.
- **Флажки на треке** (`routeFlags`, `RouteMarkers.vue`; есть и без карты, по умолчанию
  включены во всех стилях, одна кнопка в «Треке»): отметки
  километров с шагом по дистанции (`getKmMarkerStep`: не больше 6 флажков — 5 км → каждый
  км, полумарафон → 5 км, марафон → 10 км), кольцо старта, клетчатый финиш. Флажки
  в экранных координатах (при наклоне стоят вертикально); флажок вплотную к другому или
  к старту/финишу пропускается (круги по одной петле, `spreadKmMarkers`).
- Карта — фиксированная картинка (`interactive: false`): трек всегда вписан целиком.
  При наклоне `cameraForBounds` не учитывает перспективу, поэтому `fitRoute` в
  `ArtworkMap` досчитывает зум и центр по реальной проекции трека. Камера смотрит в центр
  свободной области: поля — `padding` самой камеры (`map.jumpTo({ padding })`, он смещает и
  точку схода перспективы), `cameraForBounds` — уже без своих полей. Без этого при высокой
  карточке (много показателей) область была у верхнего края, далеко к горизонту, подгонка
  не сходилась и трек при повороте улетал за карточку (было). Поля ужимаются, только если
  под трек остаётся меньше 5% карты (`MIN_FIT_AREA`) — иначе `cameraForBounds` → undefined.
- Трек — SVG поверх карты (`map.project` → `RouteStyleLayers`), те же стили, что без карты.
- Над показателями — столбец `share-artwork__visual` высотой до первой строки сетки
  (`reservedHeight` из `ArtworkStatsGrid`): карта блоком или пустая область, по которой
  вписывается трек при карте во весь фон.
- **График высоты** (`settings.elevation`, инструмент «График», `ElevationPanel`) —
  «полоса» в сетке показателей (`band` у `ArtworkStatsGrid`, слот `band`): занимает строку
  `elevation.row` целиком (не выше первой строки под картой), высота строки — по графику.
  Строка закрыта для показателей (`blockedRows` в `resolveStatLayout`/`getStatDropCells`).
  Перенос — долгим нажатием (выделенный — сразу): показатели сразу расступаются
  (`moveLayoutRow`), пунктир показывает место графика; бросок на строку показателей ставит
  их на прежнее место графика. 16 стилей (`buildElevationShapes` + `ElevationChart`), размер S/M/L — только
  в меню, цвет — плитка «Цвет» с «Цвет трека» внутри (`color: null`), подписи.
  Профиль — 400 точек через равные отрезки дистанции, двойное скользящее среднее, набор
  с порогом 3 м (иначе шум GPS даёт «пилу» и набор в разы больше).
- Подписей источников карты на карточке нет — так попросил пользователь.
- `shared/lib/map/maplibre.ts` задаёт URL воркера MapLibre — без него тайлы не грузятся.
- Экспорт: `preserveDrawingBuffer`, перед рендером `whenReady()` ждёт `idle` карты.
- Инструмент «Фон» в этом шаблоне заменён на «Карта» (`MAP_EDITOR_TOOLS`). «Трек» с картой
  активен и без трека на карточке — там наклон и поворот карты.
- Из песочницы Claude тайлы подложек недоступны — подложки проверять на телефоне.

## Шаблон «Телеметрия» (виджеты)

- Карточка «как приборная панель»: пресет цветов `hud`, показатели в стиле «Уголки»,
  трек «Свечение», узор-разметка на фоне (`telemetry.pattern`, по умолчанию «Сетка»). Превью в карусели — по той же
  схеме, что у остальных (трек + плашка с цифрами), отличие — сетка и свечение.
- `settings.telemetry` (`ShareTelemetrySettings`): список виджетов `widgets`
  (`{ kind, row }`), общий размер S/M/L, стиль графиков (те же 16 стилей, что у графика
  высоты), цвет (null — цвет трека), подписи (`labels` — сводка в заголовке виджета),
  узор фона `pattern`.
- **Узоры фона** (`SHARE_BACKGROUND_PATTERNS`: без узора, сетка, миллиметровка, точки,
  метки, развёртка, радар, штриховка) — в меню «Фон» плитками после «Прозрачный»
  (только «Телеметрия»), рисует `BackgroundPattern.vue` (на карточке и в плитке) — только
  CSS-градиенты и data-URI SVG (переносятся в PNG). Старый флажок `grid` в черновиках и
  шаблонах переводит `normalizeShareCardSettings` (`activity-share-settings.ts`) — он же в
  `useShareCardSettings` и `toTemplateSettings`.
- Виджеты (`SHARE_WIDGETS` в `activity-share-widgets.ts`, `ArtworkWidget.vue`): сплиты по км,
  пульсовые зоны (от максимума пульса за тренировку), графики темпа, пульса, высоты.
  Данные — `activity-share-telemetry.ts` (ряды через равные отрезки дистанции, сглаживание,
  темп с отсечкой 5–95-го процентиля), с тестами. Без пульса в GPX пульсовые виджеты
  неактивны.
- Виджеты и график высоты — **полосы** сетки показателей (`bands` у `ArtworkStatsGrid`,
  слот `band` с `{ bandKey, side }`). Горизонтальная занимает строку целиком
  (`placeBands` → `resolveStatLayout(blockedRows)` → `compactBands`). Вертикальная
  (`side: left/right`, только «Телеметрия», `allowSides`) — в боковой колонке: элемент сетки
  на две крайние колонки и строки области трека; несколько на стороне делят высоту, трек
  (`routeSlot`) ужимается между колонками. В колонке не больше `MAX_SIDE_WIDGETS` (2):
  в полную колонку не бросить (цель — строка), кнопка положения пропускает её
  (`resolveWidgetSide`). Клетки под колонками закрыты для показателей
  (`getSideBlockedCells` → `blockedCells`).
- **Вертикальная «лента»** графиков (темп, пульс, высота; фото и видео): в узкой колонке
  подробный ряд был «пилой» без шкалы, а копии «Изолиний» уходили за край карточки (было).
  Теперь ряд сглажен под длину колонки и растянут на ширину (`getTapeSeries`,
  `TAPE_SMOOTH_PX`, с тестами; тот же ряд у маркера видео), под заголовком — значения на
  краях шкалы (у края карточки → у трека), у края карточки — полоса `TAPE_LANE` со шкалой
  км (0 сверху, шаг `getKmMarkerStep`), график обрезан `clipPath` по своей области.
  Шкалы — только с «Подписями». Оформление элементов внутри SVG — атрибутами: CSS-правила
  для них html-to-image в PNG не переносит (подписи км выходили огромными, ось пропадала).
  Ключ полосы = элемент выделения:
  `elevation`, `widget-<вид>`.
- **Перенос полос** — один механизм для строк и колонок (`dropBand`, с тестами): долгое
  нажатие, за пальцем едет «призрак» (`stats-grid__ghost`), на месте броска — пунктир,
  остальные сразу расступаются (превью = `dropBand` от текущей раскладки). Цель — по центру
  «призрака» и снимку геометрии на старте: в области трека у краёв (треть ширины) — колонка
  с местом по порядку, иначе строка. Уход из строки её закрывает, приход в строку
  раздвигает. Результат — `dropBands` → `setBandPlacement` (строки + порядок колонок по
  порядку `widgets`) и `setStatPositions`. Кнопка положения на панели виджета (▬ ◧ ◨)
  тоже осталась.
- Меню «Виджеты» — только оформление (размер, цвет, «Подписи / Без» — как у графика
  высоты, стиль графиков);
  виджеты добавляются в «Добавить», убираются с панели выделенного виджета.
- Новый виджет получает строку `WIDGET_END_ROW` (1000+), не `MAX_SAFE_INTEGER`: при
  совпадении строк `placeBands` прибавляет 1, а `2^53 + 1 === 2^53` — вечный цикл (было).
- `ProfileChart` — общий SVG-график ряда 0…1 (высота, темп, пульс) для карточки и превью.
- Инструменты: Добавить, Фон, Оформление, Трек, Виджеты, Показатели (`TELEMETRY_EDITOR_TOOLS`).

## Бэкенд и аккаунты

- Контракт API — `docs/api.md` (единственный источник правды; меняя API, сначала правим его).
- Сервер — `server/` (отдельный npm-проект: Node.js + TypeScript, Fastify 5, PostgreSQL через
  `pg`, SQL-миграции в `server/migrations/`, тесты Vitest на реальной БД). Подробно —
  `server/README.md`. Корневые eslint и vitest папку `server/` не трогают.
- Авторизация — непрозрачный токен сессии (30 дней, в БД только SHA-256) в заголовке
  `Authorization: Bearer`. Не куки: фронт на GitHub Pages, бэк на другом домене, iOS Safari
  режет сторонние куки. Пароли — scrypt. Лимит 10 попыток/мин с IP на вход и регистрацию.
- **Почта = логин; сброс пароля; персональные данные.** Вход по логину без почты пробовали и
  отменили (без почты не восстановить пароль): миграция 004 удалена, 005 возвращает `email`
  базам, где 004 успела пройти (заглушка `логин@restored.invalid`, с тестом
  `migration-005.test.ts`). Регистрация — только с `consent: true`: отдельная неотмеченная
  галочка со ссылками на согласие и политику (в новой вкладке), над полями — плашка «почта
  только для входа и восстановления». В `users` — `consent_at`, `consent_version`
  (`CONSENT_VERSION` = `LEGAL.consentVersion`, меняются вместе с текстом). Сброс:
  `POST /api/auth/password/forgot` (всегда 204, письмо без ожидания — не выдаёт, есть ли
  аккаунт) → ссылка `APP_URL#/reset-password?token=` (60 мин, одноразовая, новая отменяет
  прежние, в БД — SHA-256, таблица `password_resets`) → `password/reset` меняет пароль,
  закрывает все сессии, выдаёт новую. `DELETE /api/auth/account` с паролем — удаление со
  всеми данными. Почта — `lib/mailer.ts` (nodemailer по `SMTP_URL`; без него письмо в лог
  сервера — ссылку брать оттуда; в тестах — `createMemoryMailer`). Тексты политики и
  согласия — `shared/config/legal-documents.ts`, реквизиты-заглушки — `legal.ts`.

## Запуск и деплой (как делали)

### Локально (у пользователя Ubuntu, PostgreSQL без Docker)

Один раз:
```sh
# если apt update падает на чужом репозитории (было: deb.etcher.io) — удалить его .list
# из /etc/apt/sources.list.d/, иначе apt install после && не запускается
sudo apt update && sudo apt install -y postgresql
sudo systemctl enable --now postgresql          # «active (exited)» в статусе — норма
cd /tmp                                          # чтобы sudo -u postgres не ругался на права к папке
sudo -u postgres psql -c "CREATE ROLE runvision LOGIN PASSWORD 'runvision'"
sudo -u postgres createdb -O runvision runvision
sudo -u postgres createdb -O runvision runvision_test
cd ~/WebstormProjects/run-vision/server && npm install && cp .env.example .env && npm run migrate
```
Каждый раз — из корня: `npm run dev` (= `dev:all`; фронт http://localhost:5173/run-vision/ +
сервер http://localhost:3000, Ctrl+C останавливает оба; недостающие пакеты фронта и сервера, `server/.env` и новые миграции — сами: `scripts/ensure-deps.mjs` (predev) и `scripts/prepare-server.mjs`; без этого после `pull` с новым пакетом Vite отдавал 500 «Failed to resolve import» — было с `mp4-muxer`). Раньше `npm run dev` поднимал только Vite → вход падал с `ERR_CONNECTION_REFUSED`, а без миграции после `git pull` — `relation "templates" does not exist` (было). Вручную — `cd server && npm run migrate`. Проверка сервера — `/api/health` → `{"ok":true}`.
Vite не на 5173 → добавить его адрес в `CORS_ORIGINS` в `server/.env`.
Вариант с Docker — `cd server && docker compose up -d` (до установки Docker не дошли).

### Смотреть базу

DBeaver (`sudo snap install dbeaver-ce`) → новое соединение PostgreSQL: `localhost:5432`,
база/пользователь/пароль `runvision`. Таблицы: `users`, `sessions`, `templates`, `schema_migrations`.
Проверить Pro — поменять `plan` на `pro` у себя и обновить страницу. `runvision_test`
не трогать — её чистят тесты. Прод-базу — так же, строкой подключения из Neon + SSL.

### Прод

Остановить на время: Render → сервис → Settings → **Suspend Web Service** (Resume — вернуть);
сайт — Settings → Pages → «⋯» у адреса сайта → Unpublish site (вернуть — Actions → Run workflow); Neon
засыпает сам без запросов.

- **База** — Neon (бесплатно, регион Frankfurt), строка подключения `…?sslmode=require`
  (если не подключается — убрать `&channel_binding=require`).
- **Сервер** — Render, Web Service `run-vision` → https://run-vision.onrender.com, ветка
  `main`, Free. Root Directory **`server`** (без него Render собирает корень и падает с
  `Missing script: "start:prod"` — было), Build `npm ci && npm run build`, Start
  `npm run start:prod` (миграции, потом сервер), Health Check Path `/api/health`.
  Переменные: `DATABASE_URL` (Neon), `CORS_ORIGINS=https://maxrusmos.github.io` (без `/` и
  пути), `TRUST_PROXY=true`, `NODE_VERSION=22`; `PORT` задаёт Render.
- **Фронт** — GitHub Pages: адрес API вшивается при сборке из переменной репозитория
  `VITE_API_URL=https://run-vision.onrender.com` (Settings → Secrets and variables → Actions →
  **Variables**, не Secrets). После смены переменной сайт надо пересобрать: Actions →
  Deploy to GitHub Pages → Run workflow (`workflow_dispatch`) или любой пуш в `main`.
  Без пересборки сайт ходит на `localhost:3000` → «Сервер недоступен» (было).
- Пуш в `main` обновляет и Render, и Pages.
- Бесплатный Render засыпает через 15 мин, старт до минуты — фронт будит его при открытии
  (`wakeApi` в `main.ts`, потом `auth.init()`). Позже — платный тариф ($7/мес).
- Диагностика «Сервер недоступен»: в логах Render запросы раз в 5 с с `10.x` — это его
  проверка здоровья; нет `OPTIONS`/`POST /api/auth/*` при входе → сайт стучится не туда
  (`VITE_API_URL`/пересборка); есть `OPTIONS` без `POST` → `CORS_ORIGINS`.
- Из песочницы Claude onrender.com и github.io недоступны (403 прокси) — проверяет пользователь.

## Мои шаблоны (сохранённое оформление)

- Только для вошедших. Шаблон = настройки карточки (`ShareCardSettings`) + шаблон-основа +
  тип (`shareType`: фото или видео, не меняется; миграция 003, старые — фото) + название; **без GPX, без фото фона и без текста названия** (`toTemplateSettings`) —
  применяется к любой тренировке. API — `/api/templates` (`docs/api.md`), сервер —
  `server/src/modules/templates`, таблица `templates` (миграция 002).
- **Видео-шаблоны** — всё как у фото, но свой редактор: звезда видео-редактора сохраняет
  шаблон с `shareType: 'video'`, применение и «Редактировать шаблон» открывают видео-редактор
  (`getTemplateEditorRoute`; роутер переводит ссылку `?template=` в редактор своего типа).
  Черновики и связи с шаблонами у фото и видео свои (`setLink`/`getLink(shareType,
  base)`, ключ `тип:основа`; ключи старых сессий без типа — фото): звезда фото-редактора не
  обновляет видео-шаблон. Кабинет: фильтр «Все / Фото / Видео» (`SegmentedGroup`, по
  умолчанию «Все»), значок типа слева сверху на плитке.
- **Звезда в редакторе** (`FavoriteTemplateButton`, в капсуле после «Сбросить», слот
  `history-extra` у `EditorTopBar`): без связи — «Сохранить» с названием; карточка, открытая
  из сохранённого шаблона (`links` в `share-drafts.store`, переживают перезагрузку), —
  «Обновить» / «Как новый». Звезда закрашена, пока карточка совпадает с шаблоном
  (`isSameTemplateSettings`: ключи сортируются — jsonb переставляет их).
- Стор — `saved-templates.store.ts` (список, `fetchOne`, создание/изменение/удаление;
  при смене пользователя очищается). Действия из кабинета — `useApplySavedTemplate`:
  - **«Создать карточку по шаблону»** (`applyToActivity`) — обычный редактор на своей
    тренировке: шаблон становится черновиком своей основы + связь (звезда обновит шаблон),
    «Сохранить» — PNG, «назад» — к выбору стиля. Своей тренировки нет (на странице шаблона
    демо) — кнопка «Загрузить GPX и создать карточку» сама открывает выбор файла (`GpxImportButton`,
    + «Показать все файлы» для iPhone) и после импорта сразу открывает редактор, без `/`.
    `hasOwnActivity` там не реактивен: иначе кнопка пропадает по `v-if` до `imported` (было).
  - **«Редактировать шаблон»** (`editTemplate`) — **режим шаблона**: редактор с
    `?template=<id>`. Роутер заранее грузит шаблон и тренировку: свою (или из сессии), а без
    неё — демо-пробежку (`demo-activity.ts`, в стор тренировки НЕ кладётся —
    `getLoadedDemoActivity()`). В режиме: полоса `TemplateEditBar` под шапкой («Шаблон «…»»,
    сохранено ли, «на демо-пробежке»), «Сохранить» обновляет шаблон («Сохранено» и
    неактивна без изменений), PNG не делается, звезды нет, черновики не пишутся.
    «Сбросить» — к последнему сохранённому виду шаблона (`resetSettings(to)`), без
    изменений неактивна.
    «Назад» — к странице шаблона; есть изменения — `TemplateLeaveDialog` (сохранить и
    выйти / выйти без сохранения / остаться) через `onBeforeRouteLeave`, т.е. и на жест
    «назад» браузера. Демо-пробежку картинкой сохранить нельзя.
- `router-view` в `AppLayout` с `:key="fullPath"` — редактор с другим `?template=` (или без)
  создаётся заново.
- Кабинет: верхняя строка `PageTopRow` (круглая «назад» + заголовок + действия справа).
  «Мои шаблоны» — «назад» туда, откуда пришли (`history.state.back`, иначе `/`); плитки —
  простое превью (`TemplateRoutePreview` в цветах шаблона) и иконка удаления в правом
  верхнем углу (кнопка — соседка ссылки, не внутри). Страница шаблона — **без прокрутки**
  (flex-колонка, превью `flex: 1`, карточка `ShareCardArtwork` в `FitToBox`, `inert`) на
  своей тренировке или демо; удаление — иконкой справа в верхней строке, внизу только
  «Создать карточку по шаблону» и «Редактировать шаблон». Подтверждение удаления —
  общий `DeleteTemplateDialog`. Пункт «Мои шаблоны» — в меню аккаунта.
- `useShareCardSettings` кладёт `initialSettings` поверх значений шаблона: новые поля
  настроек у старых черновиков и шаблонов берутся по умолчанию.

## Черновики и сессия

- **Черновики карточек** — `stores/share-drafts.store.ts`: по одному на шаблон в фото и в
  видео (ключ `photo:minimal` / `video:minimal`; `getDraft`/`saveDraft(shareType, шаблон)`,
  превью — `peekDraft`; ключи старых сессий без типа — фото, `normalizeKeys`). Редактор стартует с черновика (`initialSettings` в `useShareCardSettings`) и
  пишет его на каждое изменение; карточка как по шаблону (`isDefault()`) → черновика нет.
  Новый GPX (`importGpx`) черновики сбрасывает. История отмены — заново при каждом входе.
- **Карусель**: у шаблона с черновиком — пометка «Ваш вариант», а превью то же простое
  (трек + плашка), только в цветах черновика: фон, трек, текст (`colors` у
  `TemplateRoutePreview`, CSS-переменные `--preview-*`). Готовую карточку в превью не
  показываем — так решил пользователь. Выбранный шаблон — по центру (`center-active`).
- **Фото фона** в черновике — object URL: редактор при уходе освобождает все свои URL,
  кроме текущего (его держит черновик); черновики освобождают свои в `clear()`.
- **Сессия вкладки** — `stores/work-session.ts`: GPX (`activity.sourceFile`), тип/шаблон и
  черновики (+ файлы фото) пишутся в IndexedDB (`shared/lib/storage/idb-store.ts`, ошибки
  тихие) с задержкой 400 мс и сразу при скрытии вкладки. Метка сессии — в sessionStorage:
  перезагрузка (iOS выгружает вкладку, пока делишься картинкой) возвращает работу, новая
  вкладка — начинает с нуля (старую запись удаляет). Восстановление — в `router.beforeEach`
  для страниц с `requiresActivity`; без GPX запись не перезаписывается. Тесты — с моком
  idb-store (jsdom-файлы не проходят `structuredClone`), сам idb-store — с `fake-indexeddb`.

## Корзина (удаление перетаскиванием)

- Пока элемент карточки тащат, нижнюю панель инструментов закрывает корзина
  (`EditorTrashZone`, всегда на одном месте, вне карточки); отпустили над ней — элемент
  удалён (отмена возвращает). Общее состояние — `dragTrash` в `hooks/useDragTrash.ts`
  (зона регистрируется `useDragTrashZone`, попадание — по её прямоугольнику).
- Подключено: показатели и полосы (график высоты, виджеты) — опция `onTrash` у
  `useLongPressDrag` (onEnd(id, false) → onTrash(id)); полосы → `removeBand` из
  `ArtworkStatsGrid`; трек без карты — `onTrash` у `usePinchDrag` (корзина — только после
  сдвига одним пальцем > 8px, щипок её убирает), а невыделенный трек — долгим нажатием на
  линию (`useLongPressDrag` на зоне касания, как у показателей; рамка с углами 6px видна,
  пока тащат, и едет с треком за край); название — долгое нажатие, пока не
  редактируется (`ArtworkTitle`, после переноса фокус не включается — `justDragged`).
- **Крестиков удаления на карточке нет** (у `ArtworkElementToolbar` больше нет `remove`):
  удаление только переносом в корзину (фото фона по-прежнему удаляется в меню «Фон»).
- Пока тащат, элемент виден **за краем карточки и над корзиной**: `share-artwork--dragging`
  (`overflow: visible`) и `photo-editor--dragging` (холст `overflow: visible`, `z-index: 30`).
  Поэтому слои фона (фото, карта во весь фон, затемнение, узор) скругляются сами
  (`border-radius: inherit`), а не обрезкой карточки. Трек при этом не держится в слое
  (`center` без `clampRoutePosition`), отпустили мимо — возвращается в пределы.
- Над корзиной элемент бледнеет, а сетка не перестраивается (цель = исходное место).

## Важные грабли (уже решены — не сломать)

- **Прозрачность слоёв трека** — атрибут `opacity`, не `stroke-opacity`: иначе на iOS
  в узлах линии видны точки. Выдавливание — непрозрачные копии в полупрозрачной группе.
- **Экспорт PNG**: эффекты только из того, что html-to-image переносит в картинку —
  без `backdrop-filter`, SVG-фильтров, режимов наложения. Элементы редактора помечены
  `export-hidden`.
- **Фоновое фото в PNG**: html-to-image кладёт карточку в SVG, и iOS Safari рисует его
  в холст раньше, чем декодирует вложенную картинку, — фото попадало только со 2–3 раза.
  Поэтому при фото (`data-export-backdrop` на `<img>`) карточка рендерится без него и
  с прозрачным фоном (`toCanvas` + `filter`), а фото рисуется на холст напрямую из `<img>`
  с теми же object-fit/position и скруглением (`shared/lib/image/compose-backdrop.ts`).
- **Раскладка клона html-to-image = раскладка DOM**: клону проставляются вычисленные
  размеры (`height: …px`), а при явной высоте нижний отступ ребёнка не схлопывается через
  родителя. Название (`margin: -8px`) так сдвигало тело карточки в PNG/кадрах на 8px вниз —
  точка видео висела рядом с треком (было). Шапка — `display: flow-root`. На карточке не
  полагаться на схлопывание отступов. Проверка — сравнить прямоугольники всех элементов
  карточки в DOM и в клоне (`toSvg` → foreignObject на отдельной странице).
- **Масштаб карточки**: экранные пиксели ≠ пиксели раскладки. Жесты и FLIP переводят
  смещения через `getBoundingClientRect().width / offsetWidth`. Не использовать
  `clientWidth` для экранных расчётов.
- **Строки в настройках относительные**: `statPositions` и строки полос (`elevation.row`,
  `widget.row`) хранятся относительно первой строки под треком (`startRow`), в
  `ArtworkStatsGrid` переводятся в абсолютные и обратно. Иначе при удалении/возврате трека
  и смене плотности показатели налезали на трек или оставляли дыру.
- **Полосы и места для броска** считаются по одним «поджатым» строкам (`compactBands`
  по черновой раскладке → итоговая раскладка с ними), иначе показатель «отскакивает».
- **Жесты двумя пальцами**: `useLongPressDrag` ведёт общий учёт пальцев на экране — при
  втором пальце перенос отменяется и новый не начинается (поворот карты двигал показатели).
  Бросок на своё же место ничего не пишет в историю.
- **Данные GPX**: пульс/каденс ищутся по локальному имени тега с любым префиксом
  (`gpxtpx:hr` Strava и т.п.); без времени — `hasTimestamps: false` и время эпохи (не «сейчас»),
  без высоты — `NaN` и `hasElevation: false`; несколько `<trk>` склеиваются; битый XML —
  ошибка. Набор/максимум высоты на карточке — из того же профиля, что у графика.
  Никаких `Math.max(...массив по треку)` — на сотнях тысяч точек RangeError.
- **Выделение**: проверка «тап мимо» — через `composedPath()` (`shared/lib/dom/event-path`),
  т.к. Vue может убрать цель из DOM до всплытия события.
- **Зона касания трека** лежит под показателями (z-index 0), видимая линия — над ними.
  Сетка показателей `pointer-events: none`, сами показатели — `auto`.
- **iOS и GPX**: accept включает XML-типы; есть запасной выбор без фильтра.
- **Автозаполнение в формах входа** красило поле жёлтым поверх подписи на рамке:
  `.v-field__outline` поверх поля (z-index), заливка перекрыта тенью внутрь цвета фона,
  а анимация `rv-autofill` на `:-webkit-autofill` забирает значение в форму
  (`handleAutofill` в `AuthView`) — подпись уходит наверх, даже если не было `input`.
- **Шапка**: на телефоне 56px (`AppHeader` + `padding-top` в `AppLayout`), «Войти» — пилюля 40px.
- `scroll-snap` в рядах плиток требует `scroll-padding-inline`, иначе пропадает отступ.

## Как проверять изменения

Пользователь смотрит с телефона — проверять в Playwright с `devices['iPhone 13']`
и `hasTouch`, тач через CDP `Input.dispatchTouchEvent`. Нюансы: скрывать оверлей
vue-devtools (`#__vue-devtools-container__{display:none}`); после первого старта Vite
перезагружает страницу при оптимизации зависимостей — первый прогон теста может упасть.
Тестовые GPX — `activity_*.gpx` в корне. В песочнице (программная отрисовка) кадр
занимает секунды даже в покое — скорость мерить по времени JS, не по кадрам.

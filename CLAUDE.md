# RunVision — контекст проекта

Мобильное (в первую очередь) веб-приложение, в котором пользователь гибко настраивает
внешний вид карточки тренировки, чтобы поделиться ею. Источник данных — GPX-файл.
Сейчас готов сценарий «Фото» (PNG-карточка); «Видео» — заглушка.

Общение с пользователем, комментарии в коде и сообщения коммитов — на русском.

## Стек и команды

Vue 3.5 (`<script setup>`, TypeScript), Vuetify 4, Pinia, vue-router (hash), Vite, Vitest,
html-to-image (экспорт PNG). Деплой — GitHub Pages (`base: /run-vision/`, workflow на `main`).

```sh
npm run dev          # dev-сервер
npx vue-tsc --build  # типы
npx eslint .         # линтер (oxlint ругается только на старый код карты — это известно)
npx prettier --write src
npx vitest run       # юнит-тесты (раскладка показателей)
npx vite build
```

## Пользовательский сценарий (роуты)

1. `/` — `ImportView`: кнопка «Загрузить GPX» по центру (+ ссылка «Показать все файлы»
   для iPhone, где фильтр по типу не пускает .gpx). После загрузки → `/share`.
2. `/share` — `ShareView`: карточка тренировки, выбор «Фото / Видео», для фото — карусель
   из трёх шаблонов (Минимализм, Топография, Телеметрия; «Свой вариант» убран). Превью
   в карусели — в цветах пресета шаблона. «Продолжить» → редактор.
3. `/share/photo/editor` — `PhotoEditorView`: полноэкранный редактор (шапка приложения
   скрыта через `meta.hideAppHeader`).

4. `/login`, `/register` — `AuthView` (один компонент на оба режима, `meta.guestOnly`:
   вошедшего уводит на `/`). После входа — назад по `?redirect=` (только внутренние пути,
   `router/redirect.ts`). В `AppHeader` справа «Войти» или `UserMenu` (email, тариф, «Выйти»).

Страницы с `meta.requiresActivity` без загруженного GPX редиректят на `/`.
Старая 3D-карта (`views/activity-view`) оставлена в коде, но маршрут не зарегистрирован.

## Редактор (устройство экрана)

- Сверху `EditorTopBar` (вариант «стрелка + капсула», выбран пользователем): круглая
  кнопка ← слева, по центру капсула `EditorHistoryActions` — отменить · повторить │ сбросить
  (до 10 шагов, `useUndoRedo` с debounce 400 мс — серия изменений = один шаг; сброс —
  с диалогом), справа «Сохранить» пилюлей (рендер PNG → `ShareCardResultDialog` →
  share/скачивание). Помещается и на 320px (iPhone SE).
- «Добавить» — кнопка «Добавить все показатели» (с данными); «Показатели» — кнопка
  «удалить все». Без показателей пункт «Показатели» неактивен.
- В центре карточка `ShareCardArtwork` внутри `FitToBox`: карточка всегда видна целиком
  без прокрутки и уменьшается (CSS transform) под свободное место.
- Снизу `EditorToolbar` (инструменты из `tools/editor-tools.ts`): Добавить, Фон,
  Оформление (цветовые пресеты), Трек, Показатели. Панель `EditorToolPanel` выезжает с
  анимацией (grid-template-rows), без анимации при переключении между инструментами.
  «Трек»/«Показатели» неактивны, если элемента нет на карточке.
- Горизонтальные панели собраны из `OptionTile` / `OptionTileRow` / `ColorOptionTile`
  (одинаковая высота у Фона, Оформления и Трека). `OptionTileRow` при открытии меню сразу
  (без анимации) прокручивает ряд к выбранной плитке — по центру.
- Значения по умолчанию у шаблонов: пресет — `presetId` в `photo-templates.ts`
  (Минимализм — «Закат», Топография — «Неон», Телеметрия — «Солнце»), стили трека и
  показателей — `TEMPLATE_STYLES` в `useShareCardSettings` (Минимализм: «Тень» + «Скорость»;
  Топография: «Плитка», карта во весь фон «В тон», наклон 60°, график «Силуэт»; Телеметрия:
  «Свечение» + «Уголки», виджеты «Изолинии»: сплиты справа, над показателями пульс/темп).
  Шаблон передаётся в `useShareCardSettings` опцией `template`.

## Карточка

- Отступ 16px со всех сторон. Элементы: название (редактируется на месте, удаляется),
  трек, показатели. Выделение тапом (`SelectionFrame` + `ArtworkElementToolbar`),
  тап мимо снимает выделение.
- **Трек** (`ArtworkRoute`) — свободный слой от низа названия до низа карточки:
  двигается, масштабируется щипком (`usePinchDrag`), на десктопе — уголок и колесо.
  Стиль трека — набор слоёв-копий линии (`activity-share-route-styles.ts`), рисует
  `RouteStyleLayers` (тот же компонент — превью в меню).
  Поворот, наклон и флажки — общие для всех шаблонов, в меню «Трек» (с картой они же
  поворачивают и наклоняют карту): `routeBearing`, `routePitch` (0/35/60°),
  `routeKmMarkers`, `routeStartFinish`. Поворот на карточке — двумя пальцами (обработчик
  в `ShareCardArtwork` на всей карточке). Без карты точки считает `orientRoute`
  (`route-projection.ts`, с тестами): поворот, наклон с перспективой и заново вписывает
  в место под трек — в JS, не CSS 3D, чтобы PNG совпал с экраном. Флажки без карты —
  между точками повёрнутого трека (`index`/`t` из `getKmMarkers`), в единицах слоя.
  Превью стилей в меню «Трек» — по 200 точкам трека: с полным треком 16 плиток
  перерисовывались на каждом шаге поворота (~120 мс на шаг, меню подлагивало).
- **Показатели** — сетка из 6 колонок (⅓=2, ½=3, 1=6). Правило: в строке все показатели
  одной ширины и выровнены по её сетке. Логика — чистые функции в
  `activity-share-stat-layout.ts` (`resolveStatLayout`, `getStatDropCells`, `applyStatDrop`)
  с тестами. Перетаскивание (`useLongPressDrag`): пальцем после долгого нажатия, мышью и
  выделенный — сразу. Пунктирная сетка мест: пустая строка — по ширине перетаскиваемого,
  занятая — по ширине стоящих; бросок на другой показатель меняет их местами и размерами.
  Ширина на панели показателя — одна кнопка по кругу ⅓→½→1. Сетка «N в ряд», плотность
  (4/12/20) и стиль (16 пресетов, CSS в `ShareCardStatItem.vue`) — в меню «Показатели».
  Новый показатель получает ширину текущей сетки, если все показатели одной ширины.
- Число стилей у трека, показателей и графика одинаковое — 16; добавляя стиль одному,
  добавлять и остальным.
- Цвета: фон — в «Фоне», трек — в «Треке», текст (показатели + название) — в «Показателях».

## Шаблон «Топография» (карта)

- В `settings.map` (`ShareMapSettings`, null у других шаблонов): вид карточки `layout`
  (`block` — карта блоком, `full` — во весь фон с затемнением снизу), стиль `style`.
  Наклон и поворот карты — общие с треком (`routePitch`, `routeBearing`, меню «Трек»;
  два пальца — по всей карточке, т.к. над картой слои с `pointer-events:none`).
  При любом наклоне/повороте трек заново вписывается по центру (`fitRoute`, подгонка по
  проекции ~400 точек трека, не чаще кадра).
- Стили карты (`SHARE_MAP_STYLES` в `activity-share-map.ts`) — только Esri
  (server.arcgisonline.com: у пользователя работает, отдаёт CORS): Light/Dark Gray Canvas
  и World_Imagery + обработка растра (`raster-saturation/contrast/brightness/opacity`
  поверх цвета фона): «В тон», «Ночь», «Чертёж» (инверсия), «Винтаж», варианты спутника.
  OpenTopoMap (пёстрая), CARTO и DEM-рельеф (у пользователя не работали) — убраны.
  Превью в меню — настоящий тайл места тренировки + CSS-фильтр, приближающий обработку.
- Меню «Карта» — только вид карточки (`SegmentedGroup`) и ряд стилей.
- **Флажки на треке** (`routeKmMarkers`, `routeStartFinish`, `RouteMarkers.vue`; есть и
  без карты, по умолчанию включены только в «Топографии»): отметки
  километров с шагом по дистанции (`getKmMarkerStep`: не больше 6 флажков — 5 км → каждый
  км, полумарафон → 5 км, марафон → 10 км), кольцо старта, клетчатый финиш. Флажки
  в экранных координатах (при наклоне стоят вертикально); флажок вплотную к другому или
  к старту/финишу пропускается (круги по одной петле, `spreadKmMarkers`).
- Карта — фиксированная картинка (`interactive: false`): трек всегда вписан целиком.
  При наклоне `cameraForBounds` не учитывает перспективу, поэтому `fitRoute` в
  `ArtworkMap` досчитывает зум и центр по реальной проекции трека.
- Трек — SVG поверх карты (`map.project` → `RouteStyleLayers`), те же стили, что без карты.
- Над показателями — столбец `share-artwork__visual` высотой до первой строки сетки
  (`reservedHeight` из `ArtworkStatsGrid`): карта блоком или пустая область, по которой
  вписывается трек при карте во весь фон.
- **График высоты** (`settings.elevation`, инструмент «График», `ElevationPanel`) —
  «полоса» в сетке показателей (`band` у `ArtworkStatsGrid`, слот `band`): занимает строку
  `elevation.row` целиком (не выше первой строки под картой), высота строки — по графику.
  Строка закрыта для показателей (`blockedRows` в `resolveStatLayout`/`getStatDropCells`).
  Перенос — долгим нажатием (выделенный — сразу): показатели сразу расступаются
  (`moveLayoutRow`), пунктир показывает место графика; бросок на строку показателей ставит
  их на прежнее место графика. 16 стилей (`buildElevationShapes` + `ElevationChart`), размер S/M/L — только
  в меню, цвет — плитка «Цвет» + кнопка «Цвет трека» (`color: null`), подписи.
  Профиль — 400 точек через равные отрезки дистанции, двойное скользящее среднее, набор
  с порогом 3 м (иначе шум GPS даёт «пилу» и набор в разы больше).
- Подписей источников карты на карточке нет — так попросил пользователь.
- `shared/lib/map/maplibre.ts` задаёт URL воркера MapLibre — без него тайлы не грузятся.
- Экспорт: `preserveDrawingBuffer`, перед рендером `whenReady()` ждёт `idle` карты.
- Инструмент «Фон» в этом шаблоне заменён на «Карта» (`MAP_EDITOR_TOOLS`). «Трек» с картой
  активен и без трека на карточке — там наклон и поворот карты.
- Из песочницы Claude тайлы подложек недоступны — подложки проверять на телефоне.

## Шаблон «Телеметрия» (виджеты)

- Карточка «как приборная панель»: пресет цветов `hud`, показатели в стиле «Уголки»,
  трек «Свечение», сетка-разметка на фоне (`telemetry.grid`). Превью в карусели — по той же
  схеме, что у остальных (трек + плашка с цифрами), отличие — сетка и свечение.
- `settings.telemetry` (`ShareTelemetrySettings`): список виджетов `widgets`
  (`{ kind, row }`), общий размер S/M/L, стиль графиков (те же 16 стилей, что у графика
  высоты), цвет (null — цвет трека), сводка в заголовке, сетка.
- Виджеты (`SHARE_WIDGETS` в `activity-share-widgets.ts`, `ArtworkWidget.vue`): сплиты по км,
  пульсовые зоны (от максимума пульса за тренировку), графики темпа, пульса, высоты.
  Данные — `activity-share-telemetry.ts` (ряды через равные отрезки дистанции, сглаживание,
  темп с отсечкой 5–95-го процентиля), с тестами. Без пульса в GPX пульсовые виджеты
  неактивны.
- Виджеты и график высоты — **полосы** сетки показателей (`bands` у `ArtworkStatsGrid`,
  слот `band` с `{ bandKey, side }`). Горизонтальная занимает строку целиком
  (`placeBands` → `resolveStatLayout(blockedRows)` → `compactBands`). Вертикальная
  (`side: left/right`, только «Телеметрия», `allowSides`) — в боковой колонке: элемент сетки
  на две крайние колонки и строки области трека; несколько на стороне делят высоту, трек
  (`routeSlot`) ужимается между колонками. В колонке не больше `MAX_SIDE_WIDGETS` (2):
  в полную колонку не бросить (цель — строка), кнопка положения пропускает её
  (`resolveWidgetSide`). Клетки под колонками закрыты для показателей
  (`getSideBlockedCells` → `blockedCells`). Ключ полосы = элемент выделения:
  `elevation`, `widget-<вид>`.
- **Перенос полос** — один механизм для строк и колонок (`dropBand`, с тестами): долгое
  нажатие, за пальцем едет «призрак» (`stats-grid__ghost`), на месте броска — пунктир,
  остальные сразу расступаются (превью = `dropBand` от текущей раскладки). Цель — по центру
  «призрака» и снимку геометрии на старте: в области трека у краёв (треть ширины) — колонка
  с местом по порядку, иначе строка. Уход из строки её закрывает, приход в строку
  раздвигает. Результат — `dropBands` → `setBandPlacement` (строки + порядок колонок по
  порядку `widgets`) и `setStatPositions`. Кнопка положения на панели виджета (▬ ◧ ◨)
  тоже осталась.
- Меню «Виджеты» — только оформление (размер, цвет, сводка, сетка, стиль графиков);
  виджеты добавляются в «Добавить», убираются с панели выделенного виджета.
- Новый виджет получает строку `WIDGET_END_ROW` (1000+), не `MAX_SAFE_INTEGER`: при
  совпадении строк `placeBands` прибавляет 1, а `2^53 + 1 === 2^53` — вечный цикл (было).
- `ProfileChart` — общий SVG-график ряда 0…1 (высота, темп, пульс) для карточки и превью.
- Инструменты: Добавить, Фон, Оформление, Трек, Виджеты, Показатели (`TELEMETRY_EDITOR_TOOLS`).

## Бэкенд и аккаунты

- Контракт API — `docs/api.md` (единственный источник правды; меняя API, сначала правим его).
- Сервер — `server/` (отдельный npm-проект: Node.js + TypeScript, Fastify 5, PostgreSQL через
  `pg`, SQL-миграции в `server/migrations/`, тесты Vitest на реальной БД). Подробно —
  `server/README.md`. Корневые eslint и vitest папку `server/` не трогают.
- Авторизация — непрозрачный токен сессии (30 дней, в БД только SHA-256) в заголовке
  `Authorization: Bearer`. Не куки: фронт на GitHub Pages, бэк на другом домене, iOS Safari
  режет сторонние куки. Пароли — scrypt. Лимит 10 попыток/мин с IP на вход и регистрацию.
- Тарифы: `users.plan` (`free`/`pro`) + `plan_expires_at`; в API отдаётся действующий тариф.
  Уровни доступа `guest` < `free` < `pro`: на бэке `app.authenticate` + `requirePlan('pro')`
  (403 `PLAN_REQUIRED`), на фронте `useAccess()` и реестр фич `shared/config/features.ts`
  (пока пустой — ничего не заблокировано).
- Фронт: `shared/api/` (fetch-обёртка, `ApiError`, таймаут, `NETWORK` при недоступном
  сервере), `entities/user/`, `stores/auth.store.ts` (токен в `localStorage` `rv.auth.token`).
  Адрес API — `VITE_API_URL` (по умолчанию `http://localhost:3000`, см. `.env.example`).
  Сервер недоступен → токен не стираем (статус `offline`), приложение работает как гость;
  401 `UNAUTHORIZED` на запрос с текущим токеном → разлогин.
- Локально: `pg_ctlcluster 16 main start` (в песочнице; роль и базы `runvision`,
  `runvision_test`), `cd server && npm run migrate && npm run dev`, `npm test`.

## Важные грабли (уже решены — не сломать)

- **Прозрачность слоёв трека** — атрибут `opacity`, не `stroke-opacity`: иначе на iOS
  в узлах линии видны точки. Выдавливание — непрозрачные копии в полупрозрачной группе.
- **Экспорт PNG**: эффекты только из того, что html-to-image переносит в картинку —
  без `backdrop-filter`, SVG-фильтров, режимов наложения. Элементы редактора помечены
  `export-hidden`.
- **Фоновое фото в PNG**: html-to-image кладёт карточку в SVG, и iOS Safari рисует его
  в холст раньше, чем декодирует вложенную картинку, — фото попадало только со 2–3 раза.
  Поэтому при фото (`data-export-backdrop` на `<img>`) карточка рендерится без него и
  с прозрачным фоном (`toCanvas` + `filter`), а фото рисуется на холст напрямую из `<img>`
  с теми же object-fit/position и скруглением (`shared/lib/image/compose-backdrop.ts`).
- **Масштаб карточки**: экранные пиксели ≠ пиксели раскладки. Жесты и FLIP переводят
  смещения через `getBoundingClientRect().width / offsetWidth`. Не использовать
  `clientWidth` для экранных расчётов.
- **Строки в настройках относительные**: `statPositions` и строки полос (`elevation.row`,
  `widget.row`) хранятся относительно первой строки под треком (`startRow`), в
  `ArtworkStatsGrid` переводятся в абсолютные и обратно. Иначе при удалении/возврате трека
  и смене плотности показатели налезали на трек или оставляли дыру.
- **Полосы и места для броска** считаются по одним «поджатым» строкам (`compactBands`
  по черновой раскладке → итоговая раскладка с ними), иначе показатель «отскакивает».
- **Жесты двумя пальцами**: `useLongPressDrag` ведёт общий учёт пальцев на экране — при
  втором пальце перенос отменяется и новый не начинается (поворот карты двигал показатели).
  Бросок на своё же место ничего не пишет в историю.
- **Данные GPX**: пульс/каденс ищутся по локальному имени тега с любым префиксом
  (`gpxtpx:hr` Strava и т.п.); без времени — `hasTimestamps: false` и время эпохи (не «сейчас»),
  без высоты — `NaN` и `hasElevation: false`; несколько `<trk>` склеиваются; битый XML —
  ошибка. Набор/максимум высоты на карточке — из того же профиля, что у графика.
  Никаких `Math.max(...массив по треку)` — на сотнях тысяч точек RangeError.
- **Выделение**: проверка «тап мимо» — через `composedPath()` (`shared/lib/dom/event-path`),
  т.к. Vue может убрать цель из DOM до всплытия события.
- **Зона касания трека** лежит под показателями (z-index 0), видимая линия — над ними.
  Сетка показателей `pointer-events: none`, сами показатели — `auto`.
- **iOS и GPX**: accept включает XML-типы; есть запасной выбор без фильтра.
- `scroll-snap` в рядах плиток требует `scroll-padding-inline`, иначе пропадает отступ.

## Как проверять изменения

Пользователь смотрит с телефона — проверять в Playwright с `devices['iPhone 13']`
и `hasTouch`, тач через CDP `Input.dispatchTouchEvent`. Нюансы: скрывать оверлей
vue-devtools (`#__vue-devtools-container__{display:none}`); после первого старта Vite
перезагружает страницу при оптимизации зависимостей — первый прогон теста может упасть.
Тестовые GPX — `activity_*.gpx` в корне. В песочнице (программная отрисовка) кадр
занимает секунды даже в покое — скорость мерить по времени JS, не по кадрам.
